PLAN 001

OC consolidada por proveedor (multi-cotización)

corporate-app · corporate-api + corporate-front · Estado: propuesto (pendiente de aprobación) · 2026-09-17

Contexto

Hoy una Orden de Compra (OC) tiene relación 1:1 con una sola Cotización ganadora (purchase_orders.quote_id NOT NULL). Una Solicitud de Compra puede tener varias líneas, cada una con su propia cotización ganadora — y cuando dos o más líneas ganadoras terminan con el mismo proveedor, hoy el solicitante está obligado a emitir una OC redundante por cada línea, en vez de una sola consolidada. Se detectó al hacer QA del flujo end-to-end (solicitud SOL000000001, usuario rlobos, 4 líneas ganadas todas por el mismo proveedor) antes de pasar el ambiente de Testing a usuarios focales.

Objetivo: una OC puede cubrir varias cotizaciones ganadoras, siempre que sean de la misma solicitud y del mismo proveedor (una OC nunca puede cruzar dos proveedores — restricción real del negocio, no una decisión de diseño). Hay datos reales en dev a migrar (1 fila en purchase_orders, quote_id=4) — la migración debe ser segura/idempotente para las 3 réplicas de apidev que corren migrate.ts en paralelo en cada arranque.

Diseño

  • purchase_orders pierde quote_id (escalar 1:1) y gana request_id INT NOT NULL (FK directa a purchase_requests) — ya no hace falta pasar por una cotización para saber a qué solicitud pertenece la orden. supplier_id se mantiene igual (ya es un escalar real).
  • Tabla puente nueva purchase_order_quotes (N:M orden↔cotización) con UNIQUE(quote_id) — es la que impide, a nivel de motor, que una cotización quede cubierta por dos órdenes (reemplaza el guard de aplicación findOne({where:{quoteId}}) que no era atómico entre las 3 réplicas, misma lección que ya se aplicó para ux_cities_iata_codes/ ux_states_territorial_code).
  • goods_receipts no cambia de columnas (ya tiene quote_id), pero quoteId pasa a ser input del cliente (antes se derivaba de order.quoteId, que deja de existir como escalar) y el índice único ux_goods_receipts_order_document debe ampliarse con quote_id (con nombre nuevo ux_goods_receipts_order_quote_document, no reusar el nombre viejo con otra definición — el guard IF NOT EXISTS(name=...) nunca detectaría el cambio en una base ya migrada).

BEGIN

Bloque 3 — crear tabla puente (compartido limpia+retrofit)

IF NOT EXISTS (SELECT 1 FROM sys.tables WHERE name = 'purchase_order_quotes')
BEGIN
  CREATE TABLE purchase_order_quotes (
    id INT IDENTITY(1,1) PRIMARY KEY,
    purchase_order_id INT NOT NULL,
    quote_id INT NOT NULL,
    created_at DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME(),
    updated_at DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME(),
    CONSTRAINT fk_purchase_order_quotes_order FOREIGN KEY (purchase_order_id) REFERENCES purchase_orders(id),
    CONSTRAINT fk_purchase_order_quotes_quote FOREIGN KEY (quote_id) REFERENCES quotes(id),
    CONSTRAINT uq_purchase_order_quotes_quote UNIQUE (quote_id)
  );
END

Bloque 4 — backfill de la fila puente para la OC vieja

IF EXISTS (SELECT 1 FROM sys.columns WHERE object_id = OBJECT_ID('purchase_orders') AND name = 'quote_id')
BEGIN
  INSERT INTO purchase_order_quotes (purchase_order_id, quote_id)
  SELECT po.id, po.quote_id FROM purchase_orders po
  WHERE po.quote_id IS NOT NULL
    AND NOT EXISTS (SELECT 1 FROM purchase_order_quotes poq WHERE poq.quote_id = po.quote_id);
END

Bloque 5 — endurecer a NOT NULL solo si ya no queda ninguna fila sin backfillear

IF EXISTS (SELECT 1 FROM sys.columns WHERE object_id = OBJECT_ID('purchase_orders') AND name = 'request_id' AND is_nullable = 1)
   AND NOT EXISTS (SELECT 1 FROM purchase_orders WHERE request_id IS NULL)
BEGIN
  ALTER TABLE purchase_orders ALTER COLUMN request_id INT NOT NULL;
END

Bloque 6 — agregar la FK por nombre (no-op en limpia, ya existe con ese nombre)

IF NOT EXISTS (SELECT 1 FROM sys.foreign_keys WHERE name = 'fk_purchase_orders_request')
BEGIN
  ALTER TABLE purchase_orders ADD CONSTRAINT fk_purchase_orders_request FOREIGN KEY (request_id) REFERENCES purchase_requests(id);
END

Bloque 7 — punto de no retorno: dropea quote_id

Solo cuando ya no hay ninguna fila pendiente de backfill (ni de request_id ni de la fila puente):

IF EXISTS (SELECT 1 FROM sys.columns WHERE object_id = OBJECT_ID('purchase_orders') AND name = 'quote_id')
   AND NOT EXISTS (SELECT 1 FROM purchase_orders WHERE request_id IS NULL)
   AND NOT EXISTS (
     SELECT 1 FROM purchase_orders po
     WHERE NOT EXISTS (SELECT 1 FROM purchase_order_quotes poq WHERE poq.purchase_order_id = po.id)
   )
BEGIN
  IF EXISTS (SELECT 1 FROM sys.foreign_keys WHERE name = 'fk_purchase_orders_quote')
    ALTER TABLE purchase_orders DROP CONSTRAINT fk_purchase_orders_quote;
  IF EXISTS (SELECT 1 FROM sys.columns WHERE object_id = OBJECT_ID('purchase_orders') AND name = 'quote_id')
    ALTER TABLE purchase_orders DROP COLUMN quote_id;
END

Trazado de convergencia

En instalación limpia el CREATE ya deja la forma final y los 7 bloques son no-op. En la base dev actual (1 OC con quote_id=4, request 1 con 4 cotizaciones SELECTED del mismo proveedor, solo la línea 4 cubierta): B1 agrega columna → B2 backfillea request_id=1 → B3 crea la tabla puente → B4 inserta (order.id, 4) → B5 endurece a NOT NULL → B6 agrega la FK → B7 dropea quote_id. La OC existente sobrevive intacta; las cotizaciones 1-3 quedan pendientes y ahora sí se pueden emitir como una sola OC consolidada.

createPurchaseOrder(data: CreatePurchaseOrderInput, actorPersonId):

  1. Dedupe quoteIds = [...new Set(data.quoteIds)]; vacío → BadRequestError.
  2. QuoteModel.findAll({where:{id:{[Op.in]:quoteIds}}}); si falta alguno → NotFoundError.
  3. Alguno no SELECTED → BadRequestError (mismo mensaje que hoy, por cotización).
  4. requestIds = [...new Set(quotes.map(q=>q.requestId))]; más de uno → BadRequestError ("no puede cubrir cotizaciones de solicitudes distintas").
  5. supplierIds = [...new Set(quotes.map(q=>q.supplierId))]; más de uno → BadRequestError ("no puede cubrir cotizaciones de proveedores distintos -emita una orden por proveedor").
  6. request = getPurchaseRequestByIdOrThrow(requestId); status !== QUOTE_APPROVED → ConflictError (igual que hoy). requesterId !== actorPersonId → ForbiddenError (igual que hoy).
  7. Chequeo previo (solo para dar mensaje útil, el guard real es la constraint UNIQUE): PurchaseOrderQuoteModel.findAll({where:{quoteId:{[Op.in]:quoteIds}}}) → si hay alguna, ConflictError con el orderNumber existente.
  8. supplier = getSupplierByIdOrThrow(supplierId).
  9. Transacción: generateDocumentNumber("OC", transaction) → PurchaseOrderModel.create(...) → PurchaseOrderQuoteModel.bulkCreate(...) envuelto en try/catch: si isUniqueConstraintError(err) → ConflictError ("alguna cotización ya quedó cubierta por otra orden -recargue la pantalla"), el rollback también revierte el número de OC consumido.
  10. return getPurchaseOrderByIdOrThrow(order.id).

areAllWinningQuotesOrdered(requestId) — reescribir de comparación de cantidades a cobertura por conjunto (la comparación vieja orders.length !== winningQuotes.length queda rota apenas una OC cubre 2 cotizaciones):

async function areAllWinningQuotesOrdered(requestId: number): Promise<boolean> {
  const winningQuotes = await QuoteModel.findAll({ where: { requestId, status: "SELECTED" }, attributes: ["id"] });
  if (winningQuotes.length === 0) return false;

  const winningIds = winningQuotes.map((q) => q.id);
  const links = await PurchaseOrderQuoteModel.findAll({ where: { quoteId: { [Op.in]: winningIds } } });
  const coveredIds = new Set(links.map((l) => l.quoteId));
  if (winningIds.some((id) => !coveredIds.has(id))) return false;

  const orders = await PurchaseOrderModel.findAll({
    where: { id: { [Op.in]: [...new Set(links.map((l) => l.purchaseOrderId))] } },
    attributes: ["orderNumber"],
  });
  const request = await getPurchaseRequestByIdOrThrow(requestId);
  const folder = getAcquisitionFolder(request.requestNumber);
  return orders.every((order) => findFileByPrefix(folder, `OC-${order.orderNumber}`) !== null);
}
