PLAN 015

Contraseña por defecto no aceptada por la API (marca de cambio obligatorio)

corporate-app · corporate-api · Estado: aprobado · 2026-09-29

Contexto

En la revisión de seguridad del plan 014 (hallazgo L1) quedó en evidencia que mustChangePassword solo lo aplica el front. Un usuario con la contraseña por defecto (Nuevo Ingreso, semilla de prueba o reset del admin) puede llamar a la API directo y operar con todos los permisos de su rol sin cambiarla nunca. El usuario pidió una «marca de agua» para que la API no acepte la contraseña por defecto.

Diseño

  1. Marca al iniciar sesión. Si el usuario tiene mustChangePassword, o entra con la contraseña por defecto aunque no lo tenga, la sesión Redis guarda mustChangePassword: true. Si pidió tokens, el JWT lleva el mismo claim y /auth/refresh lo conserva.
  2. Bloqueo en authenticate. Con la marca activa, toda ruta responde 403 con reason: "password_change_required". Las excepciones son /auth/me, /auth/menu y /auth/change-password, que usan authenticateAllowingPasswordChange. /auth/logout no requiere sesión. El handshake de Socket.IO también se rechaza.
  3. Cómo se quita la marca. Solo cambiando la contraseña: el cambio invalida todas las sesiones, así que el siguiente inicio de sesión entra sin marca. No se consulta la base en cada request.
  4. Contraseña nueva. PATCH /auth/change-password rechaza la contraseña por defecto con «No puede usar la contraseña por defecto».

Archivos

  • middlewares/authenticate.ts: la marca y el middleware permisivo.
  • controllers/auth.controller.ts: marca en login y refresh; rechazo de la contraseña por defecto.
  • routes/auth.routes.ts, library/realtime/socketServer.ts.
  • types/auth.types.ts, types/redis/session.types.ts, library/errors.ts (ForbiddenError con details).
  • El front no cambia: ya redirige a /change-password.

Verificación

  • Prueba de integración:
    • un usuario recién creado inicia sesión y recibe 403 en una ruta de negocio;
    • sí puede usar /auth/me y cambiar la contraseña;
    • elegir la contraseña por defecto da 400;
    • después del cambio, un nuevo inicio de sesión no queda bloqueado.
  • tsc, pruebas unitarias e integración.
  • Revisión de seguridad antes de ir a master.
